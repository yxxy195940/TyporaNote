## 项目职责与技术事实

### 企业内容生成服务及排队可视化

本次口述支持以下职责边界：

1. 模型服务平台提供租户接入、模型调用及配置能力，面向内部产品线支撑业务。
2. 部门已有任务调度公共组件，提供资源调度以及本地、分布式排队能力。
3. 模型资源紧张时，页面除了等待，还需要看到任务当前的排队位次。
4. 候选人在已有组件基础上，基于 Redis 补充分布式排队位次或进度查询，并通过 SDK 接入模型服务平台。

简历还写有 Redis＋Lua、出入队事件跟踪、Reactor＋Sinks、容量限制和超时清理。这些可作为后续准备依据，但本段没有完整展开，不能记为本次已讲清的内容。

不能确认的细节包括 Redis 数据结构、排序依据、Lua 操作范围、位次一致性、任务取消处理、实例重启恢复，以及 AQS 在组件中的具体用途。AQS 是 Java 同步器框架，不能只用“AQS 的队列”来解释业务任务调度组件。

### 权限资源注册

本次新增的候选人口述是：开发者声明接口资源信息，服务启动时扫描并上报公共权限服务，由公共服务持久化资源并维护角色相关配置，租户面提供管理入口。

资源名称、接口、权限级别或角色等信息曾被提及，但具体注解字段、枚举和操作标识未核实。后续仍需补齐请求到来时如何识别用户与租户、查询权限、拦截未授权调用，以及权限变更如何同步。不能把“启动注册”直接当作完整鉴权机制。

## 表达复盘与后续准备

### 项目介绍需要先定义组件，再讲个人增量

面试官连续问“公共组件提供什么能力”“是消息队列还是啥”，说明业务概念和组件边界没有一次讲清。可以先用一句话说明它是部门自研的任务资源调度组件，再说明已有能力、缺失能力和本人补充的部分。

以下为基于资料整理的参考表达，不是本次原话：

> 这个平台向内部产品线提供统一的模型调用能力。模型资源紧张时，请求需要排队，用户还需要看到当前排队进度。部门已有任务资源调度组件，支持本地和分布式排队。我负责在它的基础上补充分布式排队进度查询，封装成 SDK，再接入模型服务平台。

后续追问优先准备：一个任务从提交、入队、查询、出队到执行的完整过程；同一资源跨实例如何统一排队；位次如何计算；超时、取消、重复事件如何处理。只有核实后才能把具体实现写入经历答案。

### MySQL 类型需要区分 Java 与数据库

口述时不要把 Java 的 long 作为 MySQL 类型。可按用途组织：整数和状态、字符串、时间、长文本、精确小数。数据库中整数常见 INT、BIGINT，状态可用 TINYINT，字符串常见 CHAR、VARCHAR，时间可用 DATETIME、TIMESTAMP，项目若按规范存时间戳则需核实是否用 BIGINT。涉及金额可讨论 DECIMAL，但本段没有证据说明项目实际使用。

以上为基础知识纠正及准备方向，不是补写候选人已答出所有类型。

### 空档期与工作地点表达应更直接

本次比此前多了两项信息：四月离职；朋友项目现在主要由朋友负责。后续可先回答月份和当前状态，再解释休整、参与项目的经历。是否以求职为主要安排、是否能全职投入、具体入职时间仍需本人确认。

地域方面先说明深圳是否接受，再讲实际居住安排。不要用未经核实的通勤时间支撑稳定性，也不将“可以接受深圳”写成已经租房。
