- 第一次有完整的原始转写；第二、三次依据聊天保留的语音片段，不具备完整音频、完整时间线或全部问答。
- 第二次用户明确要求模拟面试，助手当场生成的回答属于参考答案，不代表候选人在真实面试中独立回答或项目实际采用了全部方案。
- 第三次保留了候选人自己的自我介绍与离职、薪资回答。真实面试还是模拟场景未独立核验，归档只分析可见内容。
- 三次不是已确认的同一公司连续招聘流程。最初岗位描述为银行 Java 后台开发，后续详细 JD 聚焦研发效能平台；不能据此认定首次录音的机构身份。
- 转写可能识别错误。对疑似专业词按上下文整理，对不确定的机构、金额构成、离职提问和流程结果保留说明。
- 单独的 MySQL、Redis、线程知识问答，以及负责人请假场景讨论，属于补充准备材料；未记录为面试官提问的内容，不纳入第三次实际问题清单。
- 第四次按独立记录整理，转写中段缺失、重复内容已去重；不认定与前三次为同一招聘流程，也不根据结束寒暄判断面试通过。

## 后续澄清过的项目事实

以下来自用户后续确认，供准备回答时使用，不倒写成第一次录音中已经说出的内容。

| 项目事实 | 当前有效口径 |
| --- | --- |
| 日志增长量 | 项目初期每月新增约 500 万明细，原简历“日 500 万”应更正；后期单月表达到数千万 |
| 明细与统计 | 明细保留近三个月，按月分表，跨月使用 ShardingSphere；统计结果有独立表 |
| 统计查询优化 | 历史统计从实时明细聚合改为查询统计表，相关统计接口控制在 3 秒内；不能把该指标归到深分页改造 |
| 重算 | 通过接口按日期及条件重新计算完整结果，并覆盖对应统计记录；零结果清理、并发重算和事务边界尚未确认 |
| 人数口径 | 同一用户同一天调用十次算一个人；跨天或合并维度的去重人数不能直接相加 |
| 深分页 | 支持跳到最后几页，按时间戳排序；用户回忆“应该先查 ID 再关联明细”，具体 SQL 与效果待核实 |
| 平台架构 | 租户面、运行面、系统面三面隔离；具体进程、部署及故障隔离边界待核实 |
| 配置同步 | Redis 发布订阅、本地缓存及接口定时拉取兜底 |
| 流控 | Redis 支持分钟、日两个粒度；具体算法、窗口、计数维度、Lua 实现及失败计数规则尚未确认 |
| 权限与调用链 | 系统平台通用权限、租户级权限，租户可配置权限；权限→限流→Prompt 安全校验→模型网关 |
| 模型适配 | 模型名称映射 Spring 管理的 ModelClient，各 Client 适配对应模型协议 |
| 排队可视职责 | 第四次口述：基于部门已有本地与分布式调度排队组件，使用 Redis 补充分布式位次查询，并通过 SDK 接入模型服务；底层数据结构和 AQS 用途待核实 |
| 权限资源注册 | 第四次口述：接口声明资源信息，启动扫描注册至公共权限服务，集中持久化并维护角色；注解名称及运行时鉴权细节待核实 |

## 各次记录合起来最需要补的内容

1. Java 基础：线程与任务的区别、六种状态、线程池、CAS 和 AQS。
2. 数据库：联合索引、回表与覆盖索引、EXPLAIN、深分页、统计口径与重算正确性。
3. 项目证据：FlowChain 发布瓶颈及改动、流控的原子实现、性能指标的环境与统计口径。
4. 综合表达：60—90 秒自我介绍、直接回答离职问题、统一固定月薪与年度总收入的口径。
